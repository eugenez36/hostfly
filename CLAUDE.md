# Рабочие соглашения проекта hostfly

Обзор проекта и структура — в [`README.md`](README.md). Здесь то, что не выводится из кода
и на чём легко ошибиться.

## Контуры: dev и прод

**Сервер, к которому есть FTP-доступ, — это dev, а не продакшен.**

| Хост | IP | Что это |
|---|---|---|
| `mydev.hostfly.by` | `85.209.148.71` | dev-контур, целиком под htpasswd |
| `my.hostfly.by` | `45.87.219.188` | продакшен, **FTP-доступа нет** |

Локальная папка `ftp/` — зеркало dev-сервера. Заливать туда безопасно, прод это не задевает.

### Три ловушки, на которых легко ошибиться

1. **Путь внутри скомпилированных Smarty-шаблонов** на dev выглядит как
   `/home/nginx/domains/my.hostfly.by/public/...`. Это только имя каталога вхоста.
   По нему нельзя заключать, что работаешь с продом.
2. **Статика на dev и проде совпадает байт-в-байт** (`custom.css`, `overrides.css`,
   `custom.js`), поэтому сравнение ассетов тоже не доказательство. Проверять надо DNS
   и коды ответов: dev отдаёт `401` даже при запросе с `Host: my.hostfly.by`.
3. **Прод отстаёт от dev.** На dev с 10.08.2026 лежит новая логика формы регистрации
   (`clearHiddenFields`, `clearFieldsValidation` в `includes/_clientregister.tpl`), на прод
   она не выложена — живой `register.php` рендерит старую версию. Если сверяешь живую
   страницу с шаблоном, гоняй отпечаток против **всех** версий файла, включая исторические
   из git, а не только против текущей на диске.

Из-за пункта 1 сообщение коммита `16cbf1e` («Синк темы ais **с прода**») неточно —
на самом деле синк с dev. Историю не переписывали ради одной строки.

Два FTP-аккаунта ведут в одно и то же место: `maxp` попадает в корень аккаунта,
`aisdev` — сразу в веб-корень (то, что у `maxp` лежит в `public/`). Доступы в `creds.md`
(вне репозитория).

## Две темы: `nexus` (рабочая) и `ais` (прод)

| Тема | Где активна | Роль |
|---|---|---|
| `nexus` | dev `mydev.hostfly.by` | **Рабочая.** Сток WHMCS 9.0, Bootstrap 4.5.3, FA 5.10.1. Редизайн делается здесь |
| `ais` | прод `my.hostfly.by` | Тема прода, клон Six на Bootstrap 3. **В git не входит** |

Кабинет на dev перевели с `ais` на `nexus` **12.08.2026**. До этого рабочей была `ais`,
и записи об этом дожили в документации до 27.08.2026 — на них уже один раз попались
и залили UI-кит не в ту тему.

### Как проверить, какая тема активна сейчас

Не по документации и не по тому, что лежит в `templates/`, — там живут восемь тем сразу.
Проверять по свежести компилятов Smarty:

```bash
# в листинге /public/templates_c/ смотрим даты, внутри файла — путь исходника
grep -m1 -oE "templates/[a-z0-9_-]+/" <файл>_0.file.clientareahome.tpl.php
```

27.08.2026 самый свежий компилят `nexus` был от 11:46, `ais` — от 12.08 14:08.
Второй независимый способ: `curl -s https://mydev.hostfly.by/index.php?rp=/login`
и посмотреть, из какой темы подключается CSS. PHP-страницы на dev открыты,
htpasswd висит только на статике.

### Сборка брендового слоя `nexus`

```bash
cd ftp/public/templates/nexus/_dev
npm ci
npm run build      # scss/hf-kit.scss, scss/hf-theme.scss -> ../css/
```

dart-sass, а не gulp: собираются только наши два файла. Стоковый `sass/theme.scss`
идёт тулчейном WHMCS (импортирует бутстрап из их `node_modules`) и не пересобирается.
CSS намеренно **не минифицируется** — тема в git это зеркало сервера, читаемый дифф
важнее размера.

Три слоя брендинга, зоны не смешивать:

| Файл | Что в нём | Кто подключает |
|---|---|---|
| `css/custom.css` | Палитра: значения штатных токенов темы | Сток, из `includes/head.tpl` |
| `css/hf-theme.css` | Шрифты, высоты контролов, сетка, тени, подложки статусов, оверрайды компонентов | Наша правка `head.tpl` |
| `css/hf-kit.css` | UI-кит целиком, под `.hf-kit` | Наша правка `head.tpl` |

Почему палитра именно в `custom.css`: сток подключает его последним, после `theme.min.css`,
и сам предлагает переопределять там цвета («define own pallet with brand colors»).
Так не нужно воевать с каскадом, а стоковые файлы остаются нетронутыми.

### Тема `ais` снята с версионирования

Работа идёт только на `nexus`, поэтому `ais` убрана из git (файлы остались на dev-сервере
и локально в `ftp/`, которая целиком в `.gitignore`). Понадобится глянуть, как что-то
сделано на проде, — смотреть на диске или в истории до коммита удаления.
Собирать её не нужно и опасно: старый `gulp-sass 4` тянет `node-sass@4`, который под Node 20
не собирается, а задача `styles` перезаписывает **все** CSS темы разом.

### Переводы строк — не нормализовать

`.gitattributes` содержит `* -text`: файлы хранятся побайтово. Это не стилистика,
а требование. В `nexus` все 171 `.tpl` в LF, но на сервере есть файлы и с CRLF — правило
общее и снимать его нельзя.

Откуда требование: настройка `* text=auto eol=lf` в своё время искажала **165 файлов
из 418** в теме `ais` — в репозитории они лежали в LF, а на сервере в CRLF, и деплой
перезаписал бы их целиком, зашумив все будущие диффы. У пользователя `core.autocrlf`
глобально `true`, поэтому в репозитории локально выставлен `core.autocrlf=false`.

`.editorconfig` намеренно не задаёт `end_of_line` для файлов темы — иначе редактор
конвертирует их при сохранении.

### Тема в git — это зеркало

Отслеживается `ftp/public/templates/nexus/`, и она должна совпадать с сервером
байт-в-байт. Первый коммит темы (`56a6975`) — чистый сток с dev, без наших правок:
по нему в любой момент видно, что мы изменили, и есть куда откатиться.

Полезная проверка после любых операций с историей git:

```bash
git ls-files -z | xargs -0 md5sum > /tmp/after.md5   # сверить с манифестом до
```

## Мины в шапке кабинета

### `autoCollapse('#nav', 30)`

`js/whmcs.js` на `document.ready` и на `resize` вызывает `autoCollapse('#nav', 30)`:
пока высота `#nav` **не меньше 30px**, последние пункты меню уезжают в выпадашку «Ещё».
Порог захардкожен в стоковом JS. Сейчас высота 24px — запас 6px.

Отсюда правило: у пунктов меню **нельзя** трогать `line-height`, `padding`, `height`
и `border`. Цвет, вес и переход — можно, высоту они не двигают. После любой правки
меню замерять: `document.getElementById('nav').getBoundingClientRect().height`.

Вторая часть той же мины — веб-шрифт. Подмена шрифта приходит асинхронно и `resize`
не порождает, поэтому меню может остаться померенным по метрикам фолбэка. Лечится
двумя вещами: `preload` шрифтов в `includes/head.tpl` до стилей и вызовом `resize`
по `document.fonts.ready` в нашем `js/hf-kit.js`. Стоковый `whmcs.js` не трогаем.

### Токены общие — для одной зоны пишем правила, а не меняем токен

Соблазн «сток читает токен, значит правим токен» работает не всегда. Перед сменой
значения в `custom.css` проверяйте всех потребителей:

```bash
grep -o "[^{}]*var(--ТОКЕН)[^;]*" ftp/public/templates/nexus/css/theme.css
```

Примеры, на которых это уже ловилось: `--grayscale-accented` — это не только фон
топбара, но и disabled-кнопка в формах со строметром пароля; `--text-lifted` кормит
футер, сайдбар, корзину и хлебные крошки. Локальную зону красим правилом под своим
префиксом (`header.header …`), глобальную палитру двигаем отдельной задачей.

### Поповер уведомлений живёт вне шапки

Bootstrap рендерит его в конец `<body>` (`container: 'body'` в `js/whmcs.js`),
поэтому селекторы вида `header.header .popover…` не сработают. Плюс Bootstrap жёстко
задаёт `.popover`/`.tooltip` системный шрифт — гарнитуру им нужно возвращать явно.

### Ловушка `#registration`

Страница регистрации — единственная в кабинете, где брендовый слой не работает
«просто так». В стоке есть правило с id-селектором (`css/theme.css:12600`,
исходник `sass/_registration.scss:51`):

```css
#registration .field,
#registration .form-control { border: 1px solid #DDD; color: #626262;
                              height: 36px; font-size: 13px; }
```

Специфичность (1,1,0) против (0,1,0) у наших `.form-control` — внутри
`#registration` наш слой проигрывает целиком, сколько бы поздно ни грузился.
Замерено: до правки поле было 36px/`#DDD`/13px, хотя `hf-theme.css` задавал другое.

Поэтому **любое правило для страницы регистрации пишется с префиксом
`#registration`**, зеркаля стоковый селектор. Где сток использует
`body #registration` (`theme.css:9624`) — повторять и это. То же касается
`:focus` (`:12633`), `[disabled]/[readonly]` (`:12670`), `label` (`:12558`)
и `.sub-heading span` с захардкоженным `#058` (`:12569`).

### Форма регистрации собрана явно

`clientregister.tpl` больше не выводит кастомные поля циклом `{foreach $customfields}`:
подписи приходят из админки машинными именами (`r_unp`, `passport_ser`), и цикл
печатал их как есть. Порядок, группировка и подписи заданы в шаблоне —
словарь `$LBL` в его шапке, доступ к полям по имени через `$cf`.

Сами контролы по-прежнему рендерит ядро (`{$f.input}`), поэтому `name`/`id`/`value`/
тип не расходятся с настройками поля. Есть блок-страховка: кастомное поле, добавленное
в админке и не перечисленное в `$hfKnown`, выводится в отдельной карточке, а не пропадает.

Из этого следуют два ограничения:

- **Переименовать поле в админке WHMCS нельзя** — `$cf` ищет по имени, лукап отвалится.
  Побочный эффект: серверные сообщения валидации по-прежнему показывают машинное имя
  («registrant_type необходим»), потому что WHMCS строит их из имени поля в БД.
- Атрибуты `data-type` / `data-req` на обёртках **сейчас не обрабатываются ничем**.
  Это заготовка под HOS-14 (табы) и HOS-16 (паспортный блок).

## UI-кит: изоляция под `.hf-kit`

Всё, кроме токенов в `:root`, лежит под классом `.hf-kit` — и CSS, и JS (скрипт ищет
элементы только внутри контейнеров `.hf-kit`, а не по всему документу).

Это не перестраховка. Занятые имена на момент переноса:

| Класс | Занят в шаблонах кабинета (замер по `ais`, в `nexus` не пересчитан) |
|---|---|
| `card` | 11 файлов |
| `promo` | 3 файла (+ свои SCSS-правила) |
| `feature` | 3 файла |
| `plan` | 2 файла |
| `tld` | 1 файл (+ свои SCSS-правила) |

Плюс Bootstrap занимает `.btn`, `.badge`, `.pagination`, `.tabs`, `.input`.

Глобальный сброс из превью (`*`, `html`, `body`, `img, svg { display: block }`) в тему
**не перенесён как глобальный** — он поломал бы существующие страницы. Пересобран как
правила самого `.hf-kit` и его потомков.

### Где эталон кита

**Эталон — листы Figma в `ui-kit/materials/`** (14 PNG, читаются до последнего hex).
Именно по ним сверяются значения. Файлы `ui-kit/*.css` — это первичное снятие,
сделанное ДО появления листов; после сверки они местами расходятся с темой,
поэтому источником истины больше не являются. Правки вносятся в
`nexus/_dev/scss/hf-kit/*` и проверяются рендером превью против листа.

Партиалы в `nexus/_dev/scss/hf-kit/` разбиты один-к-одному с секциями `ui-kit/components.css`,
чтобы перенос оставался сверяемым построчно. Первичное снятие лежит в `ui-kit/` —
это первичное снятие с Figma-выгрузки, из него сделан перенос в тему.

Проверка изоляции после каждой пересборки — в `css/hf-kit.css` не должно быть ни одного
правила вне `.hf-kit` и `:root`. Кит подключается на всех страницах, и любое правило,
вылезшее наружу, поедет по всему кабинету.

## Состав репозитория

В git только то, что нужно для работы над темой:

| Что | Где |
|---|---|
| Рабочая тема кабинета (dev) | `ftp/public/templates/nexus/` |
| Эталон UI-кита (листы Figma) | `ui-kit/materials/` |
| Первичное снятие кита | `ui-kit/` |
| Документация | `docs/` |
| Описание и соглашения | `README.md`, `CLAUDE.md` |

Тяжёлые артефакты — выгрузки Figma (130 МБ), скриншоты и HTML-дампы аудита,
концепт-превью, статическое превью публичного сайта, эталонная выгрузка кабинета —
**вне репозитория**: остаются в Figma и локально в `app/`, которая в `.gitignore`.
История от них очищена, Git LFS не используется.

Если понадобится вернуть что-то из них под версионирование — не добавляйте бинарные
выгрузки в основной репозиторий, они снова его раздуют.

## Что вне репозитория

- `creds.md` — доступы (кабинет, FTP dev). В `.gitignore`, в историю не попадал.
- `.idea/` — конфиг PhpStorm, включая маппинг деплоя `$PROJECT_DIR$` → `/`.
- Репозиторий **публичный**, поэтому исключены исходник коммерческого модуля
  ModulesGarden и коммерческие документы (эстимация, КП). Подробно в README.

## Открытые вопросы

- **Шрифты.** В макете NT Somic (variable, `NTSomic-VF.ttf`) + Inter. Файлов в выгрузке нет,
  в теме тоже (только Font Awesome и Glyphicons). В токенах системный фолбэк; появятся
  `.woff2` — заработает без правок кода.
- **Листы `Icons` и `Logo`** из кита в код не перенесены.
- **Противоречия внутри листа Buttons.** Замеры дают разное скругление у соседних
  размеров (L=6, M primary=8, M secondary=6, XS=8), разную толщину рамки (L и XS по 2px,
  M — 1px) и разное поведение disabled у контурных кнопок. Правку под растр отложили:
  она закрепила бы противоречие. Нужен ответ дизайнера.
- **Кегль и вес кнопок** выведены из cap-height, а не измерены напрямую: замер даёт 20px
  против 16px в коде и вес 600 против 700 у размера M. Тоже отложено.
- **`docs/` писались против `nexus`** — и это снова профильная основа: гэп-анализ
  и реестр расхождений (36 ID) считались по тем же 171 `.tpl`, что мы правим.
  Оговорка «работа идёт на `ais`, а docs про nexus» снята как ошибочная.
