# Реестр расхождений: новый дизайн Figma ↔ шаблон nexus

> **Актуальность.** Документ сравнивает Figma-дизайн со **сток-темой `nexus`**.
> Работа кабинета ведётся на теме **`ais`**, а `nexus` в проекте не используется — она
> взята только как нейтральная точка отсчёта. Выводы про непокрытые дизайном разделы
> остаются в силе, но сопоставления «дизайн ↔ шаблон» к рабочей теме напрямую
> не применяются. См. [`CLAUDE.md`](../CLAUDE.md).

Источники сравнения:
- **Дизайн** — `app/new-design/` (7 листов `final-theme/`, 14 листов `ui-kit/`)
- **Шаблон** — `ftp/public/templates/nexus/` (сток-тема WHMCS 9.0, **171 `.tpl`**)

Дата: 05.08.2026 · Полный разбор покрытия: [`gap-analysis-new-design-vs-nexus.md`](gap-analysis-new-design-vs-nexus.md)

Легенда критичности: 🔴 блокер · 🟠 высокая · 🟡 средняя · ⚪ низкая / зафиксировать

# A. Расхождения по охвату

## A-01 · Весь личный кабинет не имеет дизайна 🔴

| | |
|---|---|
| **В дизайне** | Ни одного экрана кабинета. 7 листов `final-theme/` — исключительно маркетинговые страницы сайта |
| **В шаблоне** | 171 `.tpl` сток-темы WHMCS 9.0 «Nexus» |
| **Доказательство** | `theme.yaml`: `name: "Nexus"`, `description: "The Default Theme for WHMCS 9.0"`, `author: "WHMCS Limited"` — тема не модифицирована |
| **Следствие** | Пользователь, нажав «ВОЙТИ» на новом сайте, попадает в стоковый англоязычный WHMCS. Визуальный разрыв — стопроцентный |
| **Решение** | Определить скоуп: редизайн кабинета входит в проект или нет. Если да — это отдельный, более крупный этап, чем сам сайт |

## A-02 · Корзина: кнопка в макете есть, экрана нет 🔴

| | |
|---|---|
| **В дизайне** | На макете поиска домена (`главная + Домены.png`) нарисован виджет **«Ваш заказ»** с итоговой суммой и кнопкой **«Перейти в заказ →»** |
| **В шаблоне** | Экрана заказа нет. WHMCS держит корзину в `templates/orderforms/*` — по FTP этот каталог **не выгружен** (в `ftp/public/templates/` только `nexus`) |
| **Косвенное** | В теме присутствует `sass/_cart.scss`, т.е. корзина стилизуется, но её шаблонов локально нет |
| **Следствие** | Разрыв в основной воронке продаж: путь «поиск домена → заказ» обрывается на самом коммерчески значимом шаге |
| **Решение** | 1) Выгрузить `templates/orderforms/` по FTP. 2) Спроектировать корзину и оформление заказа. Приоритет №1 |

## A-03 · Вход / регистрация / восстановление пароля 🔴

| | |
|---|---|
| **В дизайне** | В хедере есть кнопки **«ВОЙТИ»** и **«СТАТЬ КЛИЕНТОМ»** (ui-kit → Buttons, размер XS) |
| **В шаблоне** | `login.tpl`, `clientregister.tpl` (320 стр.), `password-reset-container.tpl` + 3 шага, `two-factor-challenge.tpl`, `two-factor-new-backup-code.tpl`, `user-invite-accept.tpl`, `user-verify-email.tpl`, `oauth/login.tpl` |
| **Следствие** | Обе кнопки нового хедера ведут на стоковые англоязычные экраны WHMCS. Для пользователя это самый заметный разрыв |
| **Решение** | Спроектировать блок авторизации целиком, включая 2FA и восстановление пароля. Приоритет №2 |

## A-04 · Хедер/футер авторизованного состояния 🟠

| | |
|---|---|
| **В дизайне** | Только **гостевой** хедер: логотип, утилитарная строка (Новости · Вопросы · Документы · Контакты), телефоны, мега-меню, «СТАТЬ КЛИЕНТОМ» / «ВОЙТИ» |
| **В шаблоне** | `header.tpl` под `{if $loggedin}` разворачивает целый topbar |

Элементы, отсутствующие в дизайне (все — из `header.tpl`):

- кнопка уведомлений со счётчиком и попапом `clientAlerts` (список алертов по severity: danger / warning / info / success);
- блок **«Вошли как: <Компания / ФИО>»** со ссылкой в профиль;
- переключатель аккаунтов (`routePath('user-accounts')`);
- кнопка **«Вернуться в админку»** при масквераде (`adminMasqueradingAsClient`);
- иконка корзины со счётчиком `cartItemCount`;
- поиск по базе знаний в хедере (отдельные desktop- и mobile-варианты);
- вторичная навигация `secondaryNavbar` справа;
- блок аварий `includes/network-issues-notifications.tpl`;
- баннеры `includes/validateuser.tpl` и `includes/verifyemail.tpl`;
- мастер-breadcrumb под хедером.

**Решение:** спроектировать единый каркас «сайт ↔ кабинет» — после него остальные экраны кабинета верстаются внутри готовой рамки. Приоритет №4.

# C. Расхождения по компонентам

Что **есть** в `ui-kit/` (14 листов): Colors · Typography · Logo · Icons · Buttons · Links · Input · Radio • Checkbox · Tabs · Chips · Badges · Pagination · Tooltip · Все страницы.

Ниже — чего нет. В колонке «В теме» — число вхождений CSS-класса по всем 171 `.tpl`.

## C-01 · Badges: 1 маркетинговый вместо ~30 статусов 🔴

| | |
|---|---|
| **В дизайне** | Лист `Badges.png` содержит **один** бейдж «РЕКОМЕНДУЕМ» в 7 оттенках (розовый, персиковый, жёлтый, зелёный, голубой, сиреневый, серый). Семантика оттенков не задана |
| **В шаблоне** | `sass/_colors.scss` определяет **~30 статусов** |

Статусы, не имеющие дизайн-токена:

```
pending · pending-transfer · pending-registration · active · open · completed
suspended · terminated · cancelled · expired · transferred-away · redemption
grace · fraud · customer-reply · answered · onhold · inprogress · closed
paid · unpaid · refunded · collections · payment-pending · delivered
accepted · lost · dead
```

Плюс типы пользователей: `operator` · `owner` · `authorizeduser` · `registereduser` · `subaccount` · `guest`.

**Следствие:** статус — основной носитель смысла в каждом списке кабинета (услуги, домены, счета, тикеты). Без токенов ни один список кабинета спроектировать нельзя.

**Решение:** свести ~30 статусов к 5–6 семантическим группам (успех / ожидание / предупреждение / ошибка / нейтральный / архивный) и раздать им 7 существующих оттенков. Приоритет №3.

# D. Технические расхождения

## D-01 · Шрифты 🔴

| | |
|---|---|
| **В дизайне** | **NT Somic** (заголовки, weights 400/500/600/700), **Inter** (интерфейс, 400/500), **Unbounded** (акцентные крупные цифры, ~36 px w500) |
| **Проблема** | NT Somic и Unbounded — не системные. Для self-host в теме WHMCS нужны файлы шрифтов и лицензия на веб-использование |
| **Статус** | Не решено. Отмечалось ещё в `app/figma-main/РАЗБОР-ГЛАВНОЙ-figma.md` (08.07.2026) |
| **Риск** | Без лицензии придётся подбирать замену, и вся типографическая шкала (Hero 86 px, H2 40/48, карточка 24/32 и т. д.) поедет |

---

## D-02 · Сетка и стек 🟠

| | |
|---|---|
| **В теме** | Bootstrap **4.5.3**, jQuery **1.12.4**, FontAwesome 5.10.1 (`theme.yaml`) + DataTables |
| **В дизайне** | Контейнер **~1710 px** по центру при ширине 1920 (боковые поля ~105 px), мобильный 375 px |
| **Расхождение** | Дефолтный контейнер Bootstrap 4 — 1140 px. Сетка макета не совпадает с сеткой темы |
| **Следствие** | Прямая замена CSS не сработает: нужен кастомный слой поверх BS4 с переопределением контейнера и брейкпоинтов, либо переверстка |
| **Дополнительно** | jQuery 1.12.4 — версия 2016 года; современные компоненты дизайна (карусели, аккордеоны, мега-меню) на ней реализуются с ограничениями |

---

## D-03 · Локализация 🟠

| | |
|---|---|
| **В теме** | Все строки через англоязычные `{lang key='...'}`; русского языкового пакета в синке нет. Пример из `homepage.tpl`: `{lang key='clientHomePanels.productsAndServices'}`, `{lang key='howCanWeHelp'}` |
| **В дизайне** | Всё на русском |
| **Следствие** | Помимо вёрстки нужен полный перевод кабинета. Русские строки длиннее английских на 15–30 % — это влияет на вёрстку кнопок, таблиц и меню, и должно быть учтено в макетах |

---

## D-04 · Состояния фокуса и доступность 🟡

В ките для полей и кнопок описаны default / hover / active / disabled / error. **Состояния `:focus-visible` нет.**

Для кабинета это не косметика: формы оплаты, ввод 2FA-кода и восстановление пароля должны быть проходимы с клавиатуры. Также нигде не зафиксированы контрасты — синий #0027EA на белом проходит AA, но сочетание жёлтого #FFF1A1 и светлых подложек с текстом нужно проверить.

---

## D-05 · Тёмная тема ⚪

Не предусмотрена ни в ките, ни в макетах, ни в теме. Расхождением станет только если её ждут — **нужно зафиксировать решение явно**, чтобы не всплыло на приёмке.
