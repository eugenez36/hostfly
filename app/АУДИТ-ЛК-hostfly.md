# Аудит личного кабинета Hostfly.by (WHMCS)

**Проект:** редизайн личного кабинета клиента `my.hostfly.by`
**Заказчик:** ООО «Суппорт чейн» (Hostfly.by) — хостинг-провайдер и регистратор доменов, РБ
**Дата аудита:** 08.07.2026
**Автор:** Eugene Zubovich
**Метод:** авторизованный обход под тестовым аккаунтом через headless-браузер (Playwright + Chromium), только чтение.

> ⚠️ **Важно про аккаунт:** аудит выполнен под тестовой учёткой «Евгений Тест» — **0 услуг, 0 доменов, 0 счетов, 0 тикетов**. Это позволило безопасно обойти кабинет, но детальные экраны с реальными данными (карточка услуги, управление доменом, просмотр счёта) отображают пустые состояния. Их структуру описываем по заголовкам таблиц и знанию WHMCS; для финального плана желательно получить доступ к аккаунту с активными услугами (см. вопросы заказчику).

> 🔒 **Что НЕ трогали (принцип безопасности):** ничего не заказывали, не оплачивали, не отменяли, не сохраняли формы, не отправляли тикеты, не запрашивали SMS-код, не пополняли баланс. Только GET-навигация по read-only страницам + скриншоты.

## 1. Резюме (TL;DR)

- ЛК построен на **WHMCS** (коммерческая биллинг-платформа для хостеров) с **кастомной темой клиентской части** на базе стандартной темы «Six» (Bootstrap 3), полностью локализованной под РБ.
- Это **не «сайт с нуля»**, а надстройка над WHMCS: большая часть экранов — стандартный функционал WHMCS (услуги, домены, счета, тикеты, магазин/корзина, профиль). Редизайн — это **новая тема WHMCS (шаблоны Smarty + CSS/JS)**, а не переписывание бэкенда.
- Поверх стандарта навешан ряд **кастомных модулей и доработок под Беларусь** — это главный источник сложности и рисков (см. §5). Их нельзя ломать при редизайне.
- Каталог услуг широкий: **14 категорий товаров** (облако, Bitrix, WordPress, несколько типов VPS, выделенные, 1С, почта, S3, SSL, «Регистрация в БелГИЭ») + домены (.by/.бел с аукционом).
- Оплата — через белорусские платёжные системы: **ЕРИП (raschet.by), bePaid, МТБанк, Белкарт, Visa/Mastercard, Apple Pay**.

**Беглая оценка сложности:** средняя. Верстка/тема — предсказуемый объём. Основной риск и трудозатраты — аккуратная интеграция кастомных модулей (SMS-верификация, PIN-вход, акты РБ, DNS-менеджер, аукцион доменов, кастомный магазин) в новую тему без потери функциональности. Подробно — в §8.

## 2. Технологический контекст

| Параметр | Значение |
|---|---|
| Платформа | WHMCS (client area) |
| Базовая тема | «Six» (Bootstrap 3), сильно кастомизированная |
| Шаблонизатор | Smarty (`.tpl`) |
| URL-схема | Гибрид: классический `clientarea.php?action=...` + новые SEO-маршруты `/index.php?rp=/store/<slug>`, `/index.php?rp=/account/...`, `/index.php?rp=/user/...` |
| Локализация | Русский (основной) + ~30 языков WHMCS из коробки |
| Домен ЛК | `my.hostfly.by` |
| Маркетинговый сайт | `www.hostfly.by` (отдельный, БАЗА ЗНАНИЙ/FAQ ведёт туда) |
| Разделение аккаунтов | Используется модель WHMCS «Client ↔ User» (отдельно профиль пользователя и данные клиента) |
| Загрузка списков | Таблицы (услуги/домены/счета/тикеты) подгружаются через AJAX (DataTables) |

## 4. Детальный разбор разделов

### 4.1 Вход в ЛК (`/index.php?rp=/login`)
- Форма: email + пароль, «Забыли пароль?», «Запомнить меня», кнопка «Логин». Карточка с градиентной рамкой.
- Отдельная навигация для гостя: Главная · Купить · Объявления · База знаний · Статус сети · Партнерство · Связь с нами; кнопки Регистрация / Вход.
- Скриншот: `00-login.png`.

### 4.2 Дашборд (`/clientarea.php`)
- Приветствие, хлебные крошки.
- 4 плитки-счётчика: **Услуги / Домены / Запросы / Счета** (цветные, с иконками).
- Строка поиска/регистрации домена (Зарегистрировать / Перенести).
- Левый сайдбар: **Доступный баланс** (+ Пополнить), **Ваша информация** (ФИО, адрес, телефон + Обновить), **Заказ услуги** (Купить хостинг / Зарегистрировать домен / Выход).
- Виджеты: Мои домены, Последние запросы, Активные продукты/услуги, **Регистрация домена с аукциона .by/.бел** (кастомный виджет с формой заявки).
- Скриншот: `01-dashboard.png`.

### 4.3 Продукты/услуги (`?action=services`)
- Таблица (AJAX): **Продукт/услуга · Цены · Дата следующего платежа · Статус**.
- Детальная карточка услуги (productdetails) — не видна на пустом аккаунте; в WHMCS содержит управление, апгрейд, доп.услуги, вход в панель.

### 4.4 Домены (`?action=domains`)
- Таблица: **Домен · Дата регистрации · Следующий платеж · Автопродление · Статус**.
- Массовые операции (`action=bulkdomain`).
- Связанные экраны: регистрация / перенос / продление / поиск / расширенный DNS-редактор.

### 4.5 Финансы
- **Счета** (`?action=invoices`): таблица **Счет # · Дата · Срок оплаты · Всего к оплате · Состояние**; просмотр `viewinvoice.php`.
- **Предложения/оценки** (`?action=quotes`): **Предложение # · Тема · Дата · Действительно до · Этап**.
- **Пополнить баланс** (`?action=addfunds`): форма `amount` + `paymentmethod`; примечание о возврате неиспользованных средств.
- **Акты выполненных работ** (`clientacts.php`) — *кастом РБ*: таблица актов (бухгалтерская отчётность для юрлиц).

### 4.6 Поддержка
- **Запросы** (`supporttickets.php`): **Тема · Отдел · Состояние · Важность · Последнее обновление**.
- **Создать запрос** (`submitticket.php`): выбор отдела — **Техническая поддержка · Отдел продаж · Финансовый отдел · Бухгалтерия** (последний — акты/сверки, специфика РБ).
- **Объявления / Загрузки** — со стандартным поиском.
- **База знаний** — редирект на внешний сайт `www.hostfly.by/about/faq/` (не нативный WHMCS KB!).
- **Статус сети** (`serverstatus.php`): «Сейчас нет проблем с сетью».

### 4.7 Профиль / аккаунт / безопасность
- **Личные данные** (`?action=details`) — *закрыто кастомным SMS-гейтом* (модуль `PhoneVerification`): «Ваши личные данные защищены... введите код из СМС», отправка кода на телефон. Форма редактирования — за верификацией.
- **Контакты / Суб-аккаунты** (`/account/contacts`): выбор/создание контакта; поля ФИО, компания, email, телефон, адрес, страна + **email-предпочтения** (general/invoice/support/product/domain).
- **Профиль пользователя** (`/user/profile`): имя/фамилия + смена email.
- **Изменить пароль** (`/user/password`): старый/новый/подтверждение.
- **Настройки безопасности / 2FA** (`/user/security`): рекомендация включить двухэтапную авторизацию.
- **Безопасность** (`?action=security`): управление SSO (`allow_sso`).
- **PIN подтверждения входа** (`m=loginverifypin`) — *кастом*: активация PIN-кода для входа.
- **История уведомлений** (`?action=emails`): лог писем клиенту.

### 4.8 Партнёрство (`affiliates.php`)
- Активация партнёрского аккаунта, реферальные выплаты (стандартный affiliate WHMCS).

## 5. Кастомные доработки поверх WHMCS ⚠️ (ключевое для оценки)

Это то, что отличает проект от «просто перекрасить стандартную тему». Каждый пункт нужно сохранить/перенести в новую тему и протестировать:

| # | Доработка | Где | Тип | Риск при редизайне |
|---|---|---|---|---|
| 1 | **SMS-верификация доступа к личным данным** (`m=PhoneVerification`) | Личные данные | Кастомный модуль | Высокий — свои шаблоны/JS, интеграция с SMS-шлюзом |
| 2 | **PIN подтверждения входа** (`m=loginverifypin`) | Безопасность/вход | Кастомный модуль | Средний |
| 3 | **Акты выполненных работ** (`clientacts.php`) | Финансы | Кастом РБ (бухгалтерия) | Средний — юридически значимые документы |
| 4 | **Регистрация в БелГИЭ** | Магазин | Кастомный товар/процедура | Средний |
| 5 | **Аукцион доменов .by/.бел** (виджет на дашборде) | Дашборд | Кастомный виджет + форма | Средний |
| 6 | **Расширенный DNS-редактор** (`DNSManager3`) | Домены | Сторонний модуль | Средний — свой UI внутри iframe/страницы |
| 7 | **Кастомный магазин с SEO-маршрутами** (`/store/<slug>`, промо-тарифы) | Каталог | Кастом/надстройка | Средний — много шаблонов тарифов |
| 8 | **Отдел «Бухгалтерия»** в тикетах (акты, сверки) | Поддержка | Настройка | Низкий |
| 9 | **Белорусские платёжные шлюзы** (ЕРИП/raschet, bePaid, МТБанк, Белкарт) | Оплата | Модули оплаты | Средний — тестировать checkout |
| 10 | **База знаний вынесена на внешний сайт** | Поддержка | Интеграция | Низкий |

Каждая категория — левый сайдбар категорий + «Избранное» (продлить/зарегистрировать/перенести домен, корзина) + карточки тарифов (описание, характеристики: SSD/RAM/ядра/сайты/БД/почта/SSL, цена «начиная от», кнопка «Заказать»). Скриншоты `s01…s12`, `22-cart-home`.

### 6.2 Стандартный флоу заказа WHMCS (GET-часть проверена, submit НЕ выполнялся)
```
Каталог (cart.php / store) → Выбор тарифа «Заказать»
   → Шаг «Выберите домен...» (зарегистрировать новый / перенести / использовать свой + DNS)   ✓ проверен
   → Конфигурация продукта (период оплаты, доп.опции, аддоны)
   → Корзина «Просмотр и оплата» (промокод, итог)                                              ✓ структура
   → Оформление (данные клиента / вход) → Выбор способа оплаты → Оплата
```
- **Домены:** регистрация (`www.` + TLD-селектор, «Проверить»), перенос (домен + EPP-код + подтверждение владения; .BY/.БЕЛ — бесплатно), продление. Скриншоты `25`–`28`.
- **Корзина** (`cart.php?a=view`): поле промокода «Применить», «Оформить заказ / Заказать ещё услуги». Скриншот `31-cart-view`.

## 8. Беглая оценка сложности работ (pre-plan)

> Оценка **предварительная**, до ответов заказчика и доступа к реальному аккаунту. Дана как «класс сложности» по разделам, не как коммерческое КП.

| Блок | Что делаем | Сложность | Комментарий |
|---|---|---|---|
| Вход / регистрация / восстановление | новая тема | 🟢 низкая | типовые формы WHMCS |
| Дашборд | новая тема + кастомный виджет аукциона | 🟡 средняя | верстка виджетов, счётчики |
| Услуги (список + карточка) | новая тема | 🟡 средняя | карточку нужно смотреть на живом аккаунте |
| Домены + DNS-менеджер | тема + интеграция стороннего модуля | 🟡 средняя | UI DNSManager3 может быть «чужим» |
| Финансы (счета/акты/пополнение) | тема + кастом «Акты» | 🟡 средняя | акты РБ — аккуратно |
| Поддержка (тикеты/KB/статус) | новая тема | 🟢 низкая | стандарт |
| Профиль/безопасность + SMS-гейт + PIN | тема + 2 кастом-модуля | 🔴 высокая | самый рисковый блок |
| Магазин / каталог (14 групп) | новая тема | 🟡 средняя→высокая | много шаблонов тарифов |
| Форма заказа / корзина / checkout | тема + тест платёжек | 🟡 средняя | обязательно тестировать оплату |
| Адаптив + кроссбраузерность | сквозная | 🟡 средняя | миграция с BS3 |
| **Итог** | **новая тема WHMCS** | **🟡 средняя** | Драйвер сроков — кастомные модули, а не верстка |

**Гипотеза объёма** (уточняется после ответов): это редизайн-тема WHMCS (Smarty+CSS/JS), ~15 типов уникальных экранов + магазин, при обязательной сохранности ~10 кастомных доработок. Backend/бизнес-логику WHMCS не трогаем, если заказчик не просит новых фич.

## 9. Вопросы заказчику (перед составлением плана)

**Технические**

## 11. Карта глубины: что пройдено / что НЕ пройдено

> Обход был **широким** (все пункты меню + весь гостевой контур + весь каталог), но **не глубоким** по детальным экранам. Причина структурная: тестовый аккаунт пуст (**0 услуг / 0 доменов / 0 счетов / 0 тикетов**), а детальные экраны WHMCS завязаны на объект с `id` — без данных они не открываются. Плюс сознательный принцип read-only (не заказывали / не платили / не слали тикеты / не запрашивали SMS).

### 11.1 Покрытие вширь (сделано)
- 47 HTML, 48 скриншотов, 49 JSON.
- Все пункты верхнего меню + гостевой контур + верхняя панель.
- Весь каталог: 14 групп магазина, доменные флоу (GET-часть), корзина-каркас.
- Все точки входа профиля/безопасности/поддержки/финансов — как списки/лендинги.

### 11.2 Глубокие экраны, куда провалиться НЕ удалось (0 из факта)
| Раздел | Не пройденный «глубокий» экран (WHMCS) | Почему |
|---|---|---|
| **Услуги** | Карточка услуги `clientarea.php?action=productdetails&id=…` — вкладки Управление / Апгрейд-даунгрейд / Аддоны / Отмена, вход в панель (cPanel/Plesk/VPS), модуль-специфичные действия | нет ни одной услуги → нет `id` |
| **Домены** | Управление доменом `domaindetails&id=…` — NS-серверы, EPP / registrar-lock, автопродление, WHOIS-контакты, DNS-записи, email-форвардинг, домен-аддоны | нет доменов |
| **Финансы** | Просмотр счёта `viewinvoice.php?id=…` + страница оплаты + `action=masspay`; просмотр предложения `viewquote.php?id=…`; выгрузка PDF | нет счетов/предложений |
| **Поддержка** | Просмотр тикета `viewticket.php?tid=…` (переписка / ответ / вложения / закрытие / оценка); шаг-2 создания тикета (поля отдела, KB-подсказки, аплоад) | нет тикетов + read-only (submit не выполняли) |
| **Магазин** | Конфигуратор продукта: засняли **4 из ~61 тарифа** (p112/p113/p114/p145); VPS / выделенные с выбором ОС / локации / ресурсов вглубь не разобраны | сэмпл, не полный обход |
| **Оформление** | Checkout-хвост: форма данных клиента / гость-vs-логин, выбор платёжки, страница «заказ принят», редирект на ЕРИП / bePaid | сознательно не платили |
| **Профиль** | Форма редактирования личных данных (**за SMS-гейтом** `m=PhoneVerification`); настройка 2FA (метод / QR / backup-коды); матрица прав суб-аккаунта | SMS-гейт + пустой аккаунт |
| **Партнёрство** | Кабинет после активации (реф-ссылка, статистика, вывод средств, история комиссий) | видели только страницу активации |
| **Гость** | Регистрация `register` и сброс пароля `pwreset` — формы не захвачены (есть только логин) | не обошли |
| **Кастом-модули** | Внутренний UI `DNSManager3`, форма `PhoneVerification`, `clientacts`, процедура БелГИЭ — только точки входа, не внутренние экраны | нет данных / гейт |
| **Динамика** | Модалки, ошибки валидации, 2-я страница AJAX-таблиц, фильтры, дропдаун уведомлений, **populated-состояния** вместо пустых | статичный read-only обход пустого аккаунта |

**Количественно:** каталог ≈ 61 тариф в 12 категориях, конфигуратор снят у 4 → **~93 % конфигураторов вглубь не разобрано**. Детальные экраны Услуг / Доменов / Счетов / Тикетов описаны **по знанию WHMCS, не по фактическому DOM**.

### 11.3 Что нужно, чтобы пройти вглубь до конца
1. **Аккаунт с активными услугами / доменами / счетами / тикетами** (или демо-клиент на стейджинге) — для досъёмки `productdetails` / `domaindetails` / `viewinvoice` / `viewticket`.
2. **Стейджинг WHMCS + sandbox платёжек** — безопасно пройти checkout, 2FA и создание тикета до конца.
3. **Исходники / скрины кастом-модулей** от заказчика: форма `PhoneVerification`, UI `DNSManager3`, `clientacts`, процедура БелГИЭ.

### 11.4 Влияние на оценку
Перечисленные «слепые» экраны (Услуги, Домены, Профиль/2FA, конфигуратор магазина, checkout-хвост) — **основной источник верхней границы диапазона и контингенса** в `ЭСТИМАЦИЯ-редизайн-ЛК.md`. После доступа к живому аккаунту/стейджингу диапазон сузится. Связано с рисками «только пустой тестовый аккаунт» и «дизайн только дашборда» (§5) и вопросами №2, №9 (§9).

## 12. Приложение: проблемы фронта (найденные дефекты)

**Метод:** автоматический прогон по 47 сохранённым HTML-страницам (`clientarea-audit/html/*.html`) — офлайн, без обращений к живому сайту. Регэксп-проверки на mixed-content, битые/пустые ссылки, дубли `id`, `alt`, инлайн-стили, схемы URL, `<title>`, легаси-теги. Цифры — фактические счётчики по корпусу.

### 12.1 Баги (чинить в любом случае) 🔴

| # | Дефект | Масштаб | Пример / селектор | Почему баг |
|--:|---|---|---|---|
| B1 | **Mixed content** — ссылка на сайт через `http://` на https-кабинете | 46 из 47 стр | `<a href="http://www.hostfly.by/">` (`01-dashboard.html`, `02-services.html`, …) | Браузер помечает страницу небезопасной / блокирует; бьёт по доверию и SEO. Фикс — `https://` (или протокол-relative). |
| B2 | **Телефон-заглушка** в общем хедере | весь хедер (все стр) | `tel:+375171234567` рядом с реальными `tel:+375173367373` и др. (см. `data/recon-links.json`) | Placeholder-номер уехал в прод; клик инициирует звонок на несуществующий номер. |
| B3 | **Дублирующиеся `id`** (невалидный HTML) | дашборд, DNS-менеджер, база знаний | Дашборд: `id="auconfirmadd"` ×2, причём модалка ссылается сама на себя — `role="dialog" aria-labelledby="auconfirmadd"`. DNS: `id="grouptable_0_0"` ×6, `id="dataRow.id"` ×2. KB: `id="clip0"` ×3, `id="paint0_linear"` ×2 | Дубль `id` ломает `getElementById`, `label for`, `aria-labelledby`; непредсказуемые JS-обработчики и доступность. |

### 12.2 Консистентность и архитектура навигации 🟡

| C1 | **Разнобой схем URL в одном меню** | 5 форматов | `clientarea.php?action=…` (42) · отдельные `*.php` — `supporttickets.php`, `clientacts.php`, `affiliates.php`, … (11) · `cart.php` (7) · SEO-`/index.php?rp=/…` (6) · модульные `index.php?m=…` (2). ### 12.5 Вывод
- **B1–B3** — прямые баги, независимые от редизайна; можно вынести в быстрый хотфикс.

Прямо связано с оценкой (см. `ЭСТИМАЦИЯ-редизайн-ЛК.md`, этапы «Фундамент» и «Адаптив/кроссбраузер»).

> Замечания получены статическим анализом сохранённой разметки; часть пунктов (например, поведение `href="#"` при выключенном JS) стоит перепроверить на живом стейджинге.
